# Maintaining the Documentation

This folder holds the source of the documentation site at https://ogecko.github.io/alpaca-benro-polaris/. The pages are Markdown files that read well on GitHub too. [Zensical](https://zensical.org/) builds them into the site, using `zensical.toml` in the repo root for the site settings and menu. This README isn't part of the site.

## Previewing Changes

```
uv run docs
```

This runs `zensical serve`, a live preview at http://localhost:8000/alpaca-benro-polaris/ that rebuilds as you edit. To build the site once instead, run `uv run --group docs zensical build`, which writes it to `pilot/dist/docs` (ignored by git).

## Checks

Three checks run before every deploy, and fail it if something is wrong:

* `uv run --group docs python utility/docs/check_docs.py` checks that lists render the same on the site as on GitHub. Run it with `--fix` to correct them.
* `python utility/docs/make_config_reference.py --check` checks that `config.md` matches `driver/config.toml`.
* `python utility/docs/make_api_reference.py --check` checks that `telescope-api.md` and `rotator-api.md` match the driver's code.

## Generated Files

* `config.md`, the Configuration Reference, is generated from `driver/config.toml` by `utility/docs/make_config_reference.py`. Change the setting comments in `config.toml`, then run the script, rather than editing `config.md`.
* `telescope-api.md` and `rotator-api.md`, the Telescope and Rotator API References, are generated from the endpoint classes in `driver/telescope.py` and `driver/rotator.py` by `utility/docs/make_api_reference.py`. Change the classes' docstrings, then run the script, rather than editing the pages.
* `images/abp-hero.jpg`, `images/abp-gallery.jpg` and `images/abp-satellites.jpg` are generated by `utility/docs/make_home_graphics.py` from the original photos, which aren't in the repo (see the script for its usage).

## How the Site Is Published

On every push to `main` or `dev2_2`, the GitHub Actions workflow `.github/workflows/docs.yml` runs on a fresh GitHub machine:

1. It checks out the repo and installs the docs tools with `uv`.
2. It runs the three checks above. If either fails, nothing is published.
3. It reads the docs version (for example `v2.2`) from `docs_version` in `zensical.toml`.
4. It builds the site into `pilot/dist/docs`, with its links set for `…/alpaca-benro-polaris/v2.2/`.
5. It checks out the `gh-pages` branch into a `pages` folder. That branch holds every version published so far.
6. `utility/docs/publish_version.py` merges in this version:
    * it replaces `pages/v2.2/` with the new build, leaving other versions alone,
    * it rewrites `versions.json` (the version selector) and the root `index.html` (which redirects to the newest version), and
    * it copies the files in `docs/site-root/`, such as the Google Search Console verification file, to the site root.
7. It commits and pushes the updated `gh-pages` branch, so the next run starts from it.
8. It deploys the `pages` folder to GitHub Pages.

So `pilot/dist/docs` is only a staging folder for one version: the published site is whatever the `gh-pages` branch holds. The repo's **Settings > Pages > Source** must stay set to **GitHub Actions**.

## Starting a New Version

On the new release branch (for example `dev2_3`):

1. Set `docs_version` in `zensical.toml` to the new version, for example `"v2.3"`.
2. Add the branch to the `push` branches in `.github/workflows/docs.yml`.
3. Update the version in the Alpaca Pilot app's links to the docs (search `pilot/src` for `/v2.2/`), and in the README's link to Getting Started.

The older versions stay published, and the site root redirects to the newest one.
